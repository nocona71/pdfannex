\section{Purpose}

\texttt{pdfannex-docstore} adds a command for documents served by an HTTP
docstore. It is distributed separately from the core \texttt{pdfannex}
package. The core package does not access the network or know about this
adapter.

\section{Requirements}

Use \texttt{pdfannex} dated 2026/05/01 or later, \texttt{texlua}, and
\texttt{curl}. TeX Live provides \texttt{texlua}; curl must be installed
separately and available on \texttt{PATH}. The resolver runs only during
explicit CLI operations, never while compiling.

\section{Use}

Load the companion package and use its command:

\begin{verbatim}
\usepackage{pdfannex-docstore}
\includedoc[label=contract]{contract-42}{Contract}
\end{verbatim}

The command creates the source
\texttt{pdfannex://docstore/contract-42}. An optional \texttt{rev} query
parameter selects a fixed revision:
\texttt{pdfannex://docstore/contract-42?rev=2}.

\section{Configuration}

Set \texttt{PDFANNEX\_DOCSTORE\_URL} to the HTTP service's base URL.
Optionally set \texttt{PDFANNEX\_DOCSTORE\_TOKEN} to a bearer token and
\texttt{PDFANNEX\_DOCSTORE\_TIMEOUT} to the request timeout in seconds.
Credentials are read from the environment and are not written to the lock
file. If curl is missing, the resolver advises installing it and making it
available on \texttt{PATH}.

\section{Reproducible builds}

Run \texttt{pdfannex init}, build the document once, and run
\texttt{pdfannex prepare document.tex}. The CLI stores the fetched PDF and its
SHA-256 identity. Subsequent locked builds use the stored bytes without
contacting the service or requiring curl. Run \texttt{pdfannex status} to check
for upstream changes and \texttt{pdfannex update} to accept them.

\section{Installation}

Install the core \texttt{pdfannex} package and this adapter package. The
TeX distribution should expose \texttt{pdfannex-resolver-docstore} on
\texttt{PATH}; if it does not, add the adapter's scripts directory to
\texttt{PATH}. Install curl separately when unavailable.
