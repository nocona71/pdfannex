\section{Overview}

\texttt{pdfannex} includes PDF files as annexes using \texttt{pdfpages}. Each
annex gets a hyperlink target, a PDF bookmark, an entry in an automatic list of
annexes and a label usable in cross references. It works with pdfLaTeX,
LuaLaTeX and XeLaTeX and does not depend on the document class.

Annex numbers and pages are stored in the \texttt{.aux} file, so run \LaTeX{}
twice; references show \texttt{??} on the first run.

\section{Why \texttt{pdfannex}?}

An annex is part of the host document, even when its pages come from another
PDF. Readers need to move through those pages with the same pagination as the
main document, find each annex in a list and in PDF bookmarks, and follow
references to it. Without a package, authors can include the pages but must
maintain the counters, labels, list entries, bookmarks and layout glue
themselves.

Existing packages already solve parts of this problem:
\href{https://ctan.org/pkg/pdfpages}{\texttt{pdfpages}} inserts pages from
external PDFs and provides page selection, n-up placement and hooks for table
of contents or list entries. Those are useful low-level building blocks, but
authors still have to coordinate them as a semantic annex workflow.
\href{https://ctan.org/pkg/appendix}{\texttt{appendix}} adds controls for
appendix sections and numbering in the host document; it does not insert an
external PDF as an annex. \href{https://ctan.org/pkg/hyperref}{\texttt{hyperref}}
and \href{https://ctan.org/pkg/bookmark}{\texttt{bookmark}} provide links and
PDF outlines, but do not own PDF inclusion or annex pagination.

\texttt{pdfannex} connects these pieces: \texttt{pdfpages} remains responsible
for physical page inclusion, while the LaTeX package provides annex identity,
references, a list, bookmarks and consistent per-annex options.

\section{Flexibility and extension}

Use \verb|\pdfannexsetup| for document-wide defaults, then override options on
individual annexes. Each inclusion can select pages, choose a layout, set a
frame or custom margins, control page style and pagination, and opt in or out
of list and bookmark entries. The same local-PDF workflow works without the
optional CLI or network access.

The package keeps the source question separate from the PDF inclusion
workflow. An optional CLI and resolver protocol can prepare PDFs from other
systems, while \texttt{pdfannex.sty} continues to include a local PDF. Resolver
implementations can evolve independently; they do not add provider-specific
dependencies to the basic package.

\section{Usage}

\begin{verbatim}
\usepackage{pdfannex}
...
\listofannexes
\includeannex[
  label=cv,
  layout=footer-safe
]{cv.pdf}{Curriculum vitae}
See \annexref{cv} on page \annexpageref{cv}.
\end{verbatim}


\verb|\includeannex[|\emph{options}\verb|]{|\emph{file}\verb|}{|\emph{title}\verb|}|
includes all pages of \emph{file} (or those selected by \texttt{pages}) as one
annex.

The path is a normal LaTeX argument, so escape TeX-special characters as usual.
Local paths are preserved literally, including percent sequences; for example:

\begin{verbatim}
\includeannex{scans/Steuerbescheid 2025 Ü.pdf}{Tax assessment}
\includeannex{scans/literal\%41\_draft.pdf}{Draft}
\end{verbatim}

Core tests cover spaces, Unicode, nested directories, \texttt{\%}, \texttt{\&},
\texttt{\#}, \texttt{\_}, \texttt{?}, \texttt{=}, and leading hyphens on
pdfLaTeX, XeLaTeX and LuaLaTeX. Other active characters or non-default
catcodes are not guaranteed.

\section{Useful snippets}

\paragraph{Select pages and leave room for a footer}
\begin{verbatim}
\includeannex[
  label=contract,
  pages=1-3,
  layout=footer-safe
]{contract.pdf}{Signed contract}
\end{verbatim}

\paragraph{Place pages from one PDF two-up}
\begin{verbatim}
\includeannex[
  pages=4-5,
  nup=2x1,
  page-style=empty
]{minutes.pdf}{Meeting minutes}
\end{verbatim}

\paragraph{Control document-wide defaults and references}
\begin{verbatim}
\pdfannexsetup{heading=Included documents, layout=footer-safe}
\listofannexes
See \annexref{contract} on page \annexpageref{contract}.
\end{verbatim}

\paragraph{Regenerate the checked-in example PDFs}
With \texttt{pdfannex} installed, run these commands from
\texttt{doc/examples}:
\begin{verbatim}
pdflatex sample-attachments.tex
pdflatex showcase.tex
pdflatex showcase.tex
\end{verbatim}
The second run resolves the references and list entries in the showcase.

\verb|\NewAnnexSource{|\emph{command}\verb|}{|\emph{scheme}\verb|}|
defines \emph{command} like \verb|\includeannex|, but its first mandatory
argument is a reference served by an external resolver:
\verb|\NewAnnexSource{\includedoc}{docstore}| makes
\verb|\includedoc{42}{Title}| equal to
\verb|\includeannex{pdfannex://docstore/42}{Title}|. The package accepts any
scheme name; the optional command-line tool finds the resolver program.


\verb|\pdfannexsetup{|\emph{options}\verb|}| sets defaults for later annexes.

Prints the list of annexes. \verb|\annexref{|\emph{label}\verb|}| and
\verb|\annexpageref{|\emph{label}\verb|}| give a link to the annex and its
first page. References can also be used in footnotes, headings and captions;
PDF bookmarks contain plain-text references.

\section{Reproducible inputs}

The optional \texttt{pdfannex} command records and locks annex sources so
subsequent builds use the same PDF bytes. It is installed with the package;
it requires \texttt{texlua} (provided by TeX Live).

\begin{verbatim}
pdfannex init
pdflatex document.tex
pdfannex prepare document.tex
pdfannex status document.tex
pdfannex update document.tex
pdfannex verify document.tex
\end{verbatim}

For the explicit CLI workflow, run \texttt{init} once in the project
directory. This creates \texttt{pdfannex.lock}, which opts in to recording
requests. Build once before \texttt{prepare} so the package can record each
annex source. Without the optional \texttt{latexmk} integration, do not use
\texttt{-halt-on-error} for that first build when the document contains
\texttt{pdfannex://} sources: their unresolved-source errors would stop the
run before later requests are recorded.

An optional project-local \texttt{latexmk} integration automates this
bootstrap. Add the following to \texttt{.latexmkrc}:

\begin{verbatim}
my $pdfannex_rc = `kpsewhich -format=texmfscripts pdfannex_latexmkrc`;
$pdfannex_rc =~ s/\r?\n\z//;
die "pdfannex latexmk integration not found\n"
    unless $pdfannex_rc && -f $pdfannex_rc;
require $pdfannex_rc;
\end{verbatim}

With it enabled, use \texttt{latexmk document.tex}. The helper initializes
request recording, prepares new sources after the discovery pass, and lets
\texttt{latexmk} rerun LaTeX. Preparation failures fail the build; updates to
already-locked sources remain explicit.

\texttt{prepare} resolves and locks new sources; \texttt{update} explicitly
re-resolves them; \texttt{status} checks resolver-backed sources for changes;
and \texttt{verify} checks the lock and local artifact store without contacting
resolvers. Plain file paths are handled by the CLI itself. Other sources need
an executable named \texttt{pdfannex-resolver-SCHEME} on \texttt{PATH}. The
docstore example is a separate adapter and requires \texttt{curl} when it
contacts its HTTP service. Locked rebuilds use the stored PDFs and do not need
the resolver or curl.

\section{Page size and scaling}

Annex pages keep the sheet size and orientation of the host document; pages are
never rotated or stretched. Each source page is scaled uniformly to fit the
sheet, and the aspect ratio is preserved.

\textbf{Warning:} \texttt{pdfpages} scales to fit, so source pages smaller than
the host sheet (for example an A5 PDF in an A4 document) are \emph{enlarged}
to fill it, and larger pages are shrunk. Preventing enlargement is not
supported in this version. Pages in the same PDF are fitted independently.

\section{Options}

\begin{description}
\item[\texttt{label}] Label for \verb|\annexref|.
\item[\texttt{pages}] Page range passed to \texttt{pdfpages} (default \texttt{-}).
\item[\texttt{nup}] Several source pages per sheet, passed to \texttt{pdfpages} (for example \texttt{2x1}); the annex page number and \verb|\annexpageref| refer to its first sheet. Combining different files on one sheet is not supported.
\item[\texttt{layout}] \texttt{fullpage} (default), \texttt{footer-safe}
  (scaled down to leave room for the host footer) or \texttt{framed}.
\item[\texttt{margin}, \texttt{footer-space}] Custom margin and footer area;
  the page is scaled uniformly and shifted up. They override the preset
  scale of \texttt{layout}.
\item[\texttt{frame}] Boolean; draw a frame around each page (implied by \texttt{layout=framed}).
\item[\texttt{page-style}] Page style used on annex pages (default \texttt{plain}).
\item[\texttt{pagination}] \texttt{inherit} (default) uses the current page
  counter. \texttt{continue} first ends the current page and continues the page
  counter from the physical pages already output; use it with classes that reset
  the page counter, such as \texttt{scrlttr2} with several letters.
\item[\texttt{bookmark}, \texttt{list}] Boolean; add a bookmark or list entry (default true).
\item[\texttt{annex-name}, \texttt{heading}] Words used in bookmarks and
  list entries (\texttt{Annex}) and the list heading (\texttt{Annexes}).
\end{description}
